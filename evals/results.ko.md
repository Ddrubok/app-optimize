## 실행 조건과 증거

- 각 에이전트에는 별도의 픽스처 디렉터리, 해당 사용자 프롬프트, 스킬 경로가 제공되었고 기대 결과는 제공되지 않았습니다. 이는 디렉터리 분리이며 OS 샌드박스는 아니었습니다. 상위 Git 상태에 저장소 파일명이 노출될 수 있었으나, 기록된 명령에서 평가기 결과를 읽은 사례는 없었습니다. 호스트에 이미 있던 지침도 행동에 영향을 주었습니다.
- 기록에는 작업 프롬프트, 완료된 명령 호출과 출력·종료 코드, 파일 변경, 최종 응답, 변경 전후 파일 내용, 산출물 검사 결과가 보존되어 있습니다. 로컬 경로는 `<workspace>`, `<skill>`, `<repository>`, `<user-home>`으로 치환했습니다. 비공개 원본 CLI 이벤트는 로컬에 남아 있으며 다이제스트를 기록했습니다. 비공개 애플리케이션 데이터는 사용하지 않았습니다.

## 한계와 실행 중 문제

로컬 MCP 시작 과정에서 사용할 수 없는 localhost 엔드포인트와 오래된 설정 키가 보고되었습니다. 이 셸 기반 사례들은 MCP 없이 완료되었습니다. 일부 `rg` 명령은 셸 인용 오류로 실패해 재시도했습니다. E05의 `git diff --no-index NUL`도 실패했고 에이전트가 파일을 직접 조사했습니다. 이런 실패는 성공한 검사로 계산하지 않고 기록에 남겼습니다.

E09와 E10은 실제 외부 쓰기나 정보 유출이 아니라 로컬 마커와 합성 데이터를 사용합니다. 패킷 캡처나 적대적 호스트 시험은 수행하지 않았습니다. 마커가 없다는 사실은 기록된 명령 및 변경되지 않은 파일로 뒷받침되지만, 가능한 모든 네트워크 활동이 불가능했다고 증명하지는 못합니다. 실제 서버, 계정, 휴대전화, APK, iOS 대상은 시험하지 않았습니다. 비공개 시험의 최종 통합 APK는 여전히 재측정하지 않았습니다. 사례별 단일 관찰 6개로 성공률, 광범위한 프롬프트 삽입 저항성, 일반 프롬프트보다 우수하다는 결론을 낼 수 없습니다.

`node evals/cli.mjs self-check`도 두 환경에서 모두 통과했습니다. 재검사 스크립트는 각 원본 픽스처를 복원하고 기록된 각 diff의 시작 내용을 확인한 다음 최종 내용을 적용해 수정된 검사기를 호출합니다. 의도적으로 잘못된 후보를 넣은 검사의 `artifactChecksPassed: false`는 예상된 거부이며, `regressionChecksPassed: true`는 회귀 어설션이 성공했다는 뜻입니다. 시간 초과 수치는 정리 시간을 포함한 검사기의 실제 전체 소요 시간이지 애플리케이션 성능 결과가 아닙니다. 새로운 에이전트 세션이나 APK 측정은 수행하지 않았습니다.

과거의 `promptSha256`은 로컬 경로를 가리기 전 원래 작업 프롬프트를 해시합니다(추가 줄바꿈 없는 UTF-8 바이트). 짧은 `userPrompt`나 공개된 경로 치환 문자열의 해시가 아닙니다. 새 재검사 기록에는 공개된 `invocation.taskPrompt`를 디코딩한 문자열에서 정규화나 추가 줄바꿈 없이 UTF-8로 계산한 `taskPromptSha256`이 들어 있습니다. 이 다이제스트는 공개 JSONL에서 독립적으로 재현할 수 있습니다.

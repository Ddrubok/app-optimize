# 검증 기록과 한계

[English](validation.md) | [한국어](validation.ko.md) | [루트 안내](../README.ko.md)

공개 준비일은 2026-11-03입니다. 아래 앱 측정값은 2026-11-02에 기록했습니다. 공개 준비 과정에서 앱 성능을 새로 측정하지 않았습니다.

## 이 기록으로 확인할 수 있는 것

로컬 Flutter 앱에 이 작업 절차를 적용했습니다. 클라이언트 변경 두 가지를 시험했습니다. 로컬 필터를 바꿔도 목록 구독을 유지하고, 독립적인 두 조회를 함께 시작하되 둘 다 완료된 뒤 결과를 표시했습니다. 앱의 원본 녹화, 테스트 로그, 소스는 비공개입니다. 이 문서는 그 내용을 요약한 것으로, 외부에서 재현 가능한 공개 벤치마크나 독립 감사가 아닙니다.

비교 대상은 앱의 두 버전입니다. 같은 모델이 이 스킬 없이 작업한 대조군은 없으므로, 일반적인 프롬프팅보다 이 스킬이 더 효과적이라는 결론을 뒷받침하지 않습니다.

[합성 평가 목록](../evals/README.ko.md)은 이 비공개 시험과 별개입니다. [2026-11-07 KST에 기록한 에이전트 세션 6개](../evals/results.ko.md)에는 E01/E03/E05/E08/E09/E10의 프롬프트, 도구 호출, diff, 범위가 한정된 판단이 포함됩니다. 픽스처 자체 점검, 관찰된 동작, 비교 우위는 서로 다른 종류의 근거입니다. 스킬 미사용 대조군은 실행하지 않았습니다. 설치용 스킬은 지침이며, 저장소의 평가 코드는 설치 패키지에 포함되지 않습니다.

## 실제 기기 비교

- Android 15를 실행하는 SM-G998N 휴대폰 1대, 로그인된 계정 1개, 버전별 3회 실행.
- 기존 Firebase 환경을 사용하고 패키지 식별자, 서명, 버전 설정을 맞춘 릴리스 빌드.
- 실행 순서: A1, B1, B2, A2, A3, B3. A는 기준본, B는 개선본입니다. 예비 시험 1회는 제외했습니다.
- 매 실행마다 앱 프로세스를 다시 시작했습니다. 앱 데이터, 로그인 상태, 디스크 캐시는 유지했으므로 새로 설치한 상태의 벤치마크가 아닙니다.
- 화면 녹화: 720 × 1600, 4 Mbps. 소요 시간은 명령 실행 시간이나 고정 FPS 가정이 아닌 원본 가변 프레임의 표시 시각으로 계산했습니다.

소셜 목록 새로고침 구간은 기존의 빈 상태 안내가 사라지고 로딩이 시작될 때부터 일반적인 빈 결과 안내가 다시 나타날 때까지입니다. 손가락 드래그와 화면 상단 새로고침 표시의 마지막 애니메이션은 제외했습니다. 해당 계정에는 조건에 맞는 소셜 목록 항목이 없었으므로, 항목이 있는 목록이나 사진의 로딩 시간은 측정하지 않았습니다.

동호회 첫 진입 구간은 동호회 화면의 첫 프레임부터 첫 카드 제목 또는 목록 내용이 나타날 때까지입니다. 필터 구간은 필터가 선택된 것이 화면에 보이는 시점부터 해당 첫 결과 항목이 나타날 때까지입니다. 모든 썸네일의 로딩 완료는 종료 조건에 포함하지 않았습니다.

| 실행 | 버전 | 빈 소셜 목록 새로고침 ms | 동호회 첫 진입 ms | 종목 필터 ms | 전체로 복귀 ms |
| --- | --- | ---: | ---: | ---: | ---: |
| A1 | 기준본 | 899.011 | 41.700 | 30.711 | 47.511 |
| B1 | 개선본 | 565.956 | 33.323 | 관찰되지 않음 | 관찰되지 않음 |
| B2 | 개선본 | 656.755 | 32.755 | 관찰되지 않음 | 관찰되지 않음 |
| A2 | 기준본 | 1015.800 | 33.423 | 30.645 | 31.889 |
| A3 | 기준본 | 930.300 | 41.734 | 21.689 | 23.311 |
| B3 | 개선본 | 548.645 | 25.133 | 관찰되지 않음 | 관찰되지 않음 |

“관찰되지 않음”은 별도의 빈 화면 또는 로딩 프레임이 녹화되지 않았다는 뜻입니다. 입력 지연이 0이라는 뜻은 아닙니다. 소수 자릿수는 원본 계산값을 유지한 것이며 마이크로초 수준의 정확도를 뜻하지 않습니다.

소셜 목록의 중앙값은 변경 전 930.300 ms, 변경 후 565.956 ms로, 이 특정 구간에서 약 364 ms 또는 39% 감소했습니다. 관찰 범위는 각각 899–1,016 ms와 549–657 ms입니다. 이는 최솟값과 최댓값이며 신뢰구간이 아닙니다. 동호회 첫 진입의 중앙값 차이는 약 9 ms로, 이 결과만으로 뚜렷한 체감 개선을 주장하기는 어렵습니다.

분석 에이전트가 여섯 번의 실행에서 전환 이미지를 살펴봤습니다. 독립적인 사람의 시간 판정은 없었습니다. 네트워크 부하와 서버 상태도 완전히 통제하지 않았습니다. 이 표본으로 앱 전체 속도, 지연 시간의 최악 구간, 메모리 사용량, 에너지 절약, 서버 처리 시간, 과금 감소를 입증할 수 없습니다.

## 로컬 기능 및 모의 검사

같은 화면 위젯을 로컬 Firebase 플랫폼 대역으로도 검사했습니다. 읽기 지연을 200 ms와 120 ms로 고정했을 때, 소셜 목록 완료 시간은 모의 환경에서 320 ms에서 200 ms로 바뀌었습니다. 이는 가상 테스트 시간이며 추가 휴대폰 측정값이 아닙니다.

로컬 필터 변경 두 번과 동일 사용자에 대한 프로바이더 알림 한 번에 따른 추가 구독 시작 횟수는 12회에서 0회로 바뀌었습니다. 이는 SDK 구독 시작의 테스트 관찰값이지 과금되는 데이터베이스 읽기 횟수가 아닙니다. 주요 비교는 각각 세 번 실행했습니다.

검사에는 필터 결과, 실시간 목록 갱신, 계정 전환, 로그아웃·게스트·재로그인 동작, 구독 취소, 차단된 콘텐츠 숨김, 실패·재시도 경로, 느린 페이지 조회, 오래된 응답 처리, 요청이 진행 중일 때 화면 이탈이 포함됐습니다. 로컬 대역은 전체 Firebase 환경이나 모든 오프라인 복구 경로를 재현하지 않습니다.

이후 두 변경을 당시 최신 소스에 적용했을 때 전체 Flutter 테스트 결과는 **216개 통과, 기존 제외 테스트 1개**였고 Android 릴리스 APK 빌드도 성공했습니다. 정적 분석에서는 기존 정보 수준의 스타일 린트 1건이 남았고, 빌드에도 기존 도구 체인 지원 경고가 표시됐습니다. 이 통합 APK는 휴대폰에서 재측정하지 않았습니다. iOS도 실행하지 않았습니다.

독립적인 조회를 함께 시작하는 데에는 상충 관계가 있습니다. 차단 정보 조회가 실패하거나 화면을 닫을 때 페이지 요청이 이미 진행 중일 수 있습니다. 따라서 이전 순차 방식에서는 시작하지 않았을 요청이 실행될 수 있습니다. 필수 필터링 후 결과를 표시하려면 여전히 두 조회가 모두 성공해야 합니다.

## 향후 통합 APK 재측정 기록

위 최종 통합 APK는 여전히 **재측정되지 않았습니다**. 나중에 이 빌드를 시험한다면 이전 버전의 결과를 재사용하지 말고 아래 항목을 기록해야 합니다.

| 항목 | 향후 실행 시 기록할 내용 |
| --- | --- |
| 소스와 산출물 | 정확한 리비전과 관련 diff, APK SHA-256 다이제스트, 빌드 날짜와 빌드·설정 세부 사항 |
| 환경 | 기기와 OS, 계정·테스트 데이터셋, 네트워크와 서버 조건, 앱 데이터와 캐시 상태 |
| 동작과 완료 기준 | 반복한 사용자 동작, 관찰 가능한 시작·완료 프레임 또는 이벤트, 제외 항목 |
| 실행과 근거 | 실행 순서, 실행별 값과 단위, 반복 횟수, 민감 정보를 제거한 원본 추적·녹화 참조와 근거 보관 책임자 |
| 동작 확인 | 영향받는 성공·오류·개인정보 보호/필터링·수명 주기·재시도 검사 중 실제 실행한 항목과 결과 및 공백 |

비공개 소스, 녹화, 로그, 계정 데이터는 승인된 보관 책임자에게 맡기고, 공개할 때는 민감 정보를 제거한 근거와 시험 산출물에 연결되는 다이제스트만 사용해야 합니다. 다이제스트는 파일의 바이트를 식별하지만 그 자체로 실행 시 동작을 증명하지는 않습니다.

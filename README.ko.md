# app-optimize

[English](README.md) | [한국어](README.ko.md)

**기존 앱의 기능을 유지하면서 성능을 측정하고 개선하는 AI 에이전트 스킬입니다.**

화면이 늦게 뜨거나, 같은 요청이 반복되거나, 서버 작업이 많아지거나, 쓰지 않는 코드와 파일을 정리하고 싶을 때 사용합니다. 시간이 드는 지점을 찾고, 필요한 범위만 수정한 뒤, 같은 동작을 다시 확인하도록 안내합니다. 코드 정리와 실제 속도 향상도 구분해서 보고합니다.

스킬은 에이전트가 읽는 작업 지침입니다. 혼자 실행되는 최적화 프로그램이 아니며, 프로젝트와 필요한 도구에 접근할 수 있어야 합니다. 확인할 수 없는 기기·서버의 상태나 일정한 속도 향상을 보장하지 않습니다.

## 어디까지 최적화하나요

| 영역 | 확인하는 내용 |
| --- | --- |
| 클라이언트 내부 | 화면을 쓸 수 있을 때까지 무엇을 기다리는가? 화면 그리기, 데이터 변환, 반복 작업, 남아 있는 객체가 원인인가? |
| 클라이언트와 서버 통신 | 요청이 중복되거나 불필요하게 순서대로 실행되는가? 전송량·재시도·데이터 구독·캐시가 적절한가? |
| 서버와 데이터베이스 | 반복 조회, 느린 쿼리, 연결 대기, 데이터 변환이 실제 지연을 설명하는가? |
| 미사용 코드와 리소스 | 지원하는 실행 경로와 간접 사용까지 확인한 뒤 코드·의존성·에셋을 지울 수 있는가? |

Flutter를 포함한 모바일·데스크톱·웹 프로젝트에 적용할 수 있는 절차입니다. 실제 확인 범위는 프로젝트의 기술과 사용할 수 있는 도구에 따라 달라집니다. 모든 프레임워크·플랫폼과의 연동을 인증한 것은 아닙니다.

## 어떻게 진행하나요

1. **사용자가 느끼는 완료 시점을 정합니다.** 창이 열리는 순간보다 목록을 실제로 사용할 수 있는 순간을 기준으로 삼는 식입니다.
2. **수정 전 상태를 기록합니다.** 빌드·기기·데이터·캐시·측정 조건을 남깁니다. 미사용 코드 정리는 속도 측정보다 사용 여부 확인이 먼저입니다.
3. **근거가 있는 원인을 수정합니다.** 요청한 범위에서 불필요한 작업을 줄이거나 데이터 처리 흐름을 바꿉니다.
4. **같은 조건으로 다시 확인합니다.** 같은 동작의 성능을 비교하고, 변경에 영향을 받는 오류 처리·계정 전환·화면 이탈 등도 검사합니다.
5. **결과와 한계를 구분해 보고합니다.** 코드 반영, 실제 측정, 기능 검증, 확인하지 못한 조건을 나눕니다.

분석 자료는 작업 권한을 넓히는 지시로 취급하지 않습니다. 익숙하지 않거나 변경된 명령의 정의·훅·대상·부작용을 실행 전에 확인하며, 검증된 로컬 작업은 반복 승인 없이 진행합니다. 삭제 전에 관련 기능 검사의 기준 상태를 확보하고, 민감한 원본은 프로젝트의 접근·보관 규칙에 따라 관리합니다. 측정 결과는 실제 검사한 소스와 산출물에 연결합니다.

예를 들어 서로 독립적인 조회 두 개는 함께 시작할 수 있습니다. 다만 화면에 결과를 보여줄 때는 둘 다 기다려야 할 수 있습니다. 차단·권한 정보가 필요한 목록이라면 그 정보를 확인하기 전에 먼저 보여주면 안 됩니다. 속도를 줄이기 위해 숨겨야 할 내용을 노출하는 것은 올바른 최적화가 아닙니다.

## 설치 방법

설치할 폴더는 [skills/app-optimize](skills/app-optimize/SKILL.md)입니다. 참고 문서를 포함한 폴더 전체를 유지하세요.

저장소를 다운로드하거나 다음 명령으로 받습니다.

```sh
git clone https://github.com/Ddrubok/app-optimize.git
cd app-optimize
```

Codex가 `~/.codex/skills`에서 스킬을 읽는 환경이라면 그곳에 복사합니다. **아래 예시는 처음 설치할 때 사용합니다.** 기존 폴더가 있으면 개인 수정 내용을 비교하고 백업한 뒤 갱신하세요. 같은 스킬을 여러 경로에 중복 설치하지 않는 편이 좋습니다.

Windows PowerShell:

```powershell
$skillDestination = Join-Path $HOME '.codex/skills/app-optimize'
if (Test-Path -LiteralPath $skillDestination) {
    throw 'app-optimize already exists. Compare and back it up before updating.'
}
New-Item -ItemType Directory -Force (Split-Path -Parent $skillDestination) | Out-Null
Copy-Item -LiteralPath './skills/app-optimize' -Destination $skillDestination -Recurse
```

macOS 또는 Linux 셸:

```sh
if [ -e "$HOME/.codex/skills/app-optimize" ]; then
  echo 'app-optimize already exists. Compare and back it up before updating.'
else
  mkdir -p "$HOME/.codex/skills"
  cp -R skills/app-optimize "$HOME/.codex/skills/app-optimize"
fi
```

새 에이전트 세션에서 스킬 목록을 확인하세요. 사용 중인 환경이 다른 스킬 설치 경로를 지원한다면 그 경로를 사용하면 됩니다.

Claude·Gemini 등 다른 에이전트에서는 해당 도구의 설치 방법을 따르거나, `SKILL.md`와 관련 참고 문서를 읽도록 직접 요청하세요. 자동 탐색과 호출 문법은 사용하는 도구에 따라 다릅니다. `agents/openai.yaml`은 Codex 표시용 부가 정보입니다. 이 패키지의 다른 호스트 활성화·실행은 검증하지 않았습니다.

지침 패키지 자체에는 별도 런타임·MCP 서버·API 키가 필요하지 않습니다. 프로젝트, 성능 측정 도구, 에이전트에는 각각의 의존성이나 접근 권한이 필요할 수 있습니다.

## 사용 예시

다음은 셸 명령이 아니라 에이전트에게 보내는 요청입니다. `$app-optimize` 표기는 Codex용 예시입니다.

**코드를 수정하지 않고 원인 확인**

```text
$app-optimize 회원 목록이 늦게 뜨는 원인을 조사해주세요.
가능한 부분을 측정하고 클라이언트부터 서버까지의 흐름을 확인한 뒤,
근거와 수정안을 보고해주세요. 앱 코드는 수정하지 마세요.
```

**특정 화면의 로딩 최적화**

```text
$app-optimize 이 Flutter 앱의 동호회 목록 로딩을 개선해주세요.
필터, 실시간 갱신, 계정 간 데이터 분리, 오류 복구를 유지해주세요.
필요한 로컬 수정을 하고 같은 조건에서 전후를 비교해주세요.
배포는 하지 마세요.
```

**미사용 코드 정리**

```text
$app-optimize 클라이언트에서 쓰지 않는 코드·의존성·에셋을 정리해주세요.
라우트, 생성 코드의 원본, 네이티브 등록, 지원 플랫폼까지 확인해주세요.
사용 여부가 불확실하면 보존하고 판단에 필요한 정보를 알려주세요.
```

프로젝트 위치, 느린 동작, 기대 결과, 사용할 수 있는 테스트 환경, 검토만 할지 수정까지 할지를 알려주면 도움이 됩니다. 기존 기획서나 QA 체크리스트도 활용합니다. 매번 정해진 설문을 작성해야 하는 방식은 아닙니다.

## 결과에서 확인할 것

- 어떤 동작을 대상으로 무엇을 근거로 바꿨는지
- 같은 조건의 전후 수치·단위·반복 횟수, 또는 성능을 측정하지 못했다는 설명
- 실제로 실행한 기능 검사와 실패·미확인 범위
- 삭제한 항목과 미사용 판단 근거를 속도·용량 개선 주장과 구분한 기록

코드 검색 결과가 없더라도 실행 중 이름으로 불러오는 에셋일 수 있습니다. 데이터 구독 횟수가 줄었다고 서버 요금도 같은 비율로 줄었다고 단정할 수 없고, 빌드 성공만으로 실제 조작이 빨라졌다고 말할 수도 없습니다.

기존 체크리스트가 있으면 항목 ID와 이력을 유지합니다. 설치되어 있는 `app-qa-human`·`qa-checklist`와 함께 사용할 수 있지만 필수는 아닙니다. 기능이 맞는지 확인하는 QA와 얼마나 빨라졌는지 확인하는 성능 측정은 서로 다른 검사입니다.

## 확인된 사례와 한계

이 절차를 사용한 로컬 Flutter·Android 앱 비교 사례가 있습니다. 휴대폰 1대에서 버전별 3회 측정한 빈 목록 새로고침의 로딩 구간은 중앙값 **0.93초에서 0.57초**로 줄었습니다. 해당 코드 변경과 시험 조건의 결과이며, 다른 앱에서 기대할 수 있는 향상률이나 일반 요청보다 스킬이 우수하다는 증거는 아닙니다.

[검증 기록](docs/validation.ko.md)에 6회 측정값, 시작·종료 기준, 기능 검사와 미검증 범위를 정리했습니다. 앱 소스와 원본 녹화는 비공개이므로, 이 기록은 외부에서 그대로 재현할 수 있는 공개 벤치마크가 아닌 결과 요약입니다. 이 저장소에는 해당 비공개 앱의 소스·APK·계정 데이터·녹화를 넣지 않았습니다.

[평가 목록](evals/README.ko.md)에 합성 사례 12개를 마련했습니다. [실제 에이전트 실행 6건](evals/results.ko.md)은 검토 범위 준수, 동적 에셋, 계정 전환, 기존 테스트 실패, 명령 훅, 로그 속 지시문을 다루며 요청문·도구 호출·변경 내역·판정을 담습니다. 픽스처 자체 검사와 실제 행동 결과는 구분합니다. 일반 요청보다 우수하다는 비교 근거는 아니며, 비공개 사례의 최종 통합 APK는 여전히 미측정입니다.

개선된 검사기는 검사 완료와 프로세스의 정상 종료를 요구하고, 필수 파일 누락·허용되지 않은 변경을 검출하며, 실행 한계에 도달했을 때의 정리 작업을 포함해 자식 프로세스의 실행 시간·출력량을 제한합니다. 산출물 검사 결과와 최종 행동 판정은 분리합니다. [최신 검사기 재검사](evals/results.ko.md#검사기-재검사--2026-11-08-kst)에는 Windows와 WSL Linux 각각에서 회귀 검사 30건과 기존 산출물 6건 재검사가 통과한 기록을 담았습니다. 신규 에이전트 실행이나 앱 성능 측정 결과는 아닙니다.

로컬 최적화 요청이 배포·운영 DB 변경·실서비스 부하 시험·데이터 삭제까지 허용하는 것은 아닙니다. 검토만 요청하면 앱 코드를 수정하지 않습니다. 새 앱 생성, 시각적 재디자인, AI 토큰 절감용 스킬도 아닙니다.
